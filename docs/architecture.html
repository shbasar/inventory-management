Request Data Flow
1
User selects a filter

FilterBar component updates shared singleton state via the useFilters() composable — four reactive refs shared across all views.

selectedPeriod.value = 'Q1-2025' selectedLocation.value = 'Tokyo' selectedCategory.value = 'Sensors' selectedStatus.value = 'Delivered'
2
Watcher fires in the active view

Each view watches the filter refs. On change it calls getCurrentFilters() which maps UI names to API param names, then triggers a fetch.

watch([selectedPeriod, selectedLocation, selectedCategory, selectedStatus], () => { loadData() })
3
api.js builds the HTTP request

Values equal to 'all' are omitted. selectedLocation maps to warehouse; selectedPeriod maps to month.

GET /api/orders?warehouse=Tokyo&category=Sensors&status=Delivered&month=Q1-2025
4
FastAPI filters in-memory data

apply_filters() chains warehouse → category (case-insensitive) → status filters. filter_by_month() expands quarters (Q1-2025 → Jan/Feb/Mar).

results = orders # full dataset results = apply_filters(results, warehouse, category, status) results = filter_by_month(results, month) # expands Q1 → [01,02,03]
5
Pydantic validates and serialises the response

FastAPI uses the declared response_model to validate and serialise each object before returning JSON.

@app.get("/api/orders", response_model=List[Order]) def get_orders(...) -> List[Order]: ...
6
Vue stores raw data and derives computed views

Raw API response is stored in a ref. All display values (summaries, charts, tables) are computed properties that update reactively.

const allOrders = ref([]) // raw — set from API const orderHealth = computed(() => // derived — auto-updates allOrders.value.reduce(...) )
